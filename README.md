# StudyFlow — планировщик учебных задач

Учебный frontend-проект для студентов на HTML5, CSS3 и JavaScript без фреймворков. Помогает собрать задания разных предметов в одном месте, видеть сроки, приоритеты и прогресс. Тема подтверждена пользователем; материалы урока 1 для отдельной сверки не предоставлены.

## Страницы

| Файл | Назначение |
| --- | --- |
| index.html | Обзор, статистика, ближайшие дедлайны и прогресс |
| tasks.html | Список задач, поиск, фильтры, сортировка и управление заданиями |
| profile.html | Учебный профиль и проверка формы |

## Функции

- Мобильное раскрываемое меню, закрытие по Escape.
- Создание и редактирование задач в модальном окне; проверка названия и даты.
- Отметка выполнения; удаление только после подтверждения.
- Поиск по названию и предмету; совместные фильтры по предмету и состоянию.
- Сортировка по сроку, названию и приоритету.
- Автоматическая статистика и процент выполнения на главной.
- Проверка имени, email и группы, сохранение профиля.
- Общие данные всех страниц в localStorage; сообщения при недоступном хранилище.
- Пустые состояния и демонстрационные задачи при первом запуске.

## Запуск

Распакуйте весь архив, а не только HTML-файлы. На Windows запустите `START.bat` и оставьте окно терминала открытым. Либо в папке проекта выполните:

```bash
python -m http.server 8000
```

Откройте http://localhost:8000/index.html. Если команда `python` недоступна, используйте `py` на Windows или `python3` на Linux/macOS. Для сохранения общих данных между страницами рекомендуется запуск через HTTP. Никакие npm-пакеты не нужны.

## Структура

- `index.html`, `tasks.html`, `profile.html` — семантические страницы.
- `css/styles.css` — общие переменные, стили компонентов, адаптивность.
- `js/app.js` — данные, события, отображение и localStorage.
- `img/study.svg` — оригинальная векторная иллюстрация.
- `scripts/build.py` — копирование сайта в dist для публикации.
- `.github/workflows/pages.yml` — автоматическая публикация GitHub Pages.
- `docs/DEFENSE.md` — объяснение кода и сценарий защиты.
- `docs/QA.md` — результаты проверок и ручной чек-лист.
- `docs/screenshots/README.md` — инструкция по скриншотам.

## Дизайн и адаптивность

Единая палитра задаётся CSS-переменными в `:root`. Для аудитории студентов выбран спокойный светлый фон с фиолетовыми акцентами. На десктопе главная содержит четыре карточки статистики и две колонки контента. При ширине до 900 px статистика перестраивается в две колонки, до 600 px меню становится раскрываемым, а панели и форма профиля располагаются в одну колонку. Вёрстка использует Flexbox и Grid. Инлайн-стилей, Bootstrap и Tailwind нет.

Используются `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`, `dialog`, `progress`, подписи полей и alt изображения. Предусмотрены видимый фокус, ссылка пропуска навигации, aria-label кнопок, aria-pressed фильтров и сообщения ошибок.

## Публикация и история Git

История разработки содержит не менее пяти последовательных осмысленных коммитов. В архиве есть `repository.bundle`, позволяющий восстановить её. Автор локальных коммитов обозначен как Student: личные фамилия и имя не предоставлены.

Публичный репозиторий GitHub пока не создан. Для окончательной сдачи создайте пустой публичный репозиторий с названием `surname-name-fullstack-frontend`, заменив surname/name своей фамилией и именем латиницей. Выполните команды из `docs/PUBLISH.md`. Простая загрузка файлов через веб-интерфейс GitHub не переносит историю — используйте bundle и git push.

После публикации внесите здесь реальные ссылки на публичный репозиторий и GitHub Pages. Выдуманные ссылки не добавлены. Размещённая версия Sites предназначена для просмотра владельцем и не заменяет публичную сдачу.

## Проверки и ограничения

Проверены синтаксис JS, локальные ссылки и структура HTML. Функциональные сценарии выполнены в Node.js с моделью DOM: создание, редактирование, удаление, отмена удаления, фильтры, валидация, сохранение, некорректные данные и недоступное хранилище. Это не полноценная браузерная проверка. Визуальную адаптивность, клавиатурную навигацию и скриншоты нужно подтвердить по `docs/QA.md`.

Серверной части, базы данных и настоящей регистрации нет. Изменения хранятся только в текущем браузере; очистка данных сайта удаляет их. Email не отправляется на сервер. Исходный интерфейс и иллюстрация подготовлены для этого проекта. На защите нужно понимать код и уметь менять его самостоятельно; ИИ использован как помощник.
